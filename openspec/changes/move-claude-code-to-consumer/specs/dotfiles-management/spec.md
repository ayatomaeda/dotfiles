## ADDED Requirements

### Requirement: 特定のエージェント製品の設定は利用側が持つ

core は、特定のエージェント製品 (Claude Code など) の設定と、その製品のためだけにある依存 (設定が呼ぶスクリプト、その製品のアプリの cask) を宣言してはならない (MUST NOT)。core のリストと `programs.*` の有効化は利用側で外せず、使うエージェントは環境によって違うためである。その製品を使う利用側が、自分の構成で宣言する。

エンジニアが日常的に使う一般的な道具 (`jq`、`ripgrep`、`fd` など) と、複数のエージェントで使う道具 (エージェント用のマルチプレクサ) は、特定のエージェントの設定が呼ぶものであっても core に置いてよい (MAY)。core に置く道具のコメントには、特定のエージェント製品の都合ではなく、core に置く理由を書かなければならない (SHALL)。

非対話のエージェントにシェル構成が波及することへの配慮 (シェルスナップショットに載る alias や関数の扱いなど) は、特定の製品の設定ではなくシェルの性質なので、core に置く。

#### Scenario: core の生成物

- **WHEN** core のモジュールだけを読み込んだ構成 (評価用の例の構成) を評価する
- **THEN** `programs.claude-code.enable` は false で、home-manager は `~/.claude/settings.json` を生成しない
- **AND** Homebrew の cask のリストに `claude` が無い

#### Scenario: エージェントの設定が呼ぶ一般的な道具

- **WHEN** 利用側が宣言したエージェントのステータスラインが `jq` を呼ぶ
- **THEN** `jq` は core が一般的な道具として宣言したものを使ってよい
- **AND** 利用側の宣言のコメントに、core の `jq` を前提にすることが書かれている

## MODIFIED Requirements

### Requirement: アプリケーション自身が書き込む設定ファイルの扱い

システムは、アプリケーション自身が実行中に書き込む設定ファイルであっても、**宣言から生成しなければならない** (SHALL)。アプリケーションによる書き込みを保存するために、書き込み可能な形式で配置してはならない (MUST NOT)。宣言が唯一の情報源であり、アプリ側で行った変更は保存されない。

この性質は利用者から見て分かりにくい (エラーは出ず、その場限りで効くアプリと、その場でも効かないアプリ (herdr の設定画面) がある) ため、**どのアプリのどの操作が保存されないのかを文書に明示しなければならない** (SHALL)。書く場所は、そのアプリの設定を宣言したリポジトリの文書とする (利用側が宣言したアプリは利用側の文書に書く)。

#### Scenario: 書き込みが発生する設定ファイルの配置

- **WHEN** 対象アプリケーションが自身の設定ファイルへ値を書き込む
- **THEN** そのファイルは宣言から生成された読み取り専用の実体である
- **AND** アプリケーションの変更は保存されず、恒久的な変更はリポジトリの宣言で行う

#### Scenario: 保存されない操作の周知

- **WHEN** アプリ自身が書き込む設定ファイルを管理下に置く
- **THEN** そのアプリのどの操作が保存されないのかが、その設定を宣言したリポジトリの README に書かれている
- **AND** 恒久的に変えるための手順 (宣言の変更と `switch`) が併記されている
