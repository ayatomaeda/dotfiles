## MODIFIED Requirements

### Requirement: ホスト固有の値をモジュールから分離する

システムは、ホストや環境によって異なる値をモジュール内に直書きしてはならない (MUST NOT)。対象には、ユーザー名、ホスト名、git の identity と署名鍵 (鍵そのものと、鍵を指す名前)、ssh の接続先、特定の環境でだけ使うパッケージ、プラットフォーム固有の外部プログラムのパスを含む。

値は利用側が与える。**モジュールがその値を読む場合に限り**、型付きの `dotfiles.*` の options として宣言しなければならない (SHALL)。モジュールが読まない値 (git の identity、ssh の接続先など) は option にせず、利用側が home-manager / nix-darwin の標準の option に直接書く (モジュールシステムがマージする)。

option を作る根拠は次のいずれかでなければならない (SHALL):

1. ホスト側が値を与える必要がある
2. 既定値を**ホスト依存の情報から導出する**必要がある (ホームディレクトリ、プラットフォーム等)

**定数を option に置き換えてはならない** (MUST NOT) — 指し先が増えるだけで何も表現しないため。「モジュールを整理したい」ことは option を作る根拠にならない (MUST NOT)。

ただし、**モジュール間でデータを受け渡すためのものはこの制限の対象外**とする。それは設定項目ではないため、`internal` を付けて設定項目と区別しなければならない (SHALL)。

#### Scenario: モジュールが読まない値

- **WHEN** 利用側が git の identity や ssh の接続先を与える
- **THEN** 利用側は `programs.git.settings.user.*` や `programs.ssh.settings.<host>` に直接書く
- **AND** そのための `dotfiles.*` の option は無い

#### Scenario: モジュールが読む値

- **WHEN** モジュールが環境ごとに違う値を読む (例: 署名鍵の名前から、agent の鍵を選ぶ)
- **THEN** その値は `dotfiles.*` の option で渡される
- **AND** 値が与えられないときの振る舞い (署名しないなど) が決まっている

#### Scenario: 既定値の導出による option

- **WHEN** option の値が現在すべてのホストで同一である
- **THEN** その既定値がホスト依存の情報から導出されていることが説明されている
- **AND** そうでない場合はその option は不要である

#### Scenario: モジュール間の受け渡し

- **WHEN** あるモジュールが導出した値を別のモジュールが必要とする
- **THEN** その受け渡しに使う option は `internal` として宣言される
- **AND** ホストが設定する対象ではないことが区別できる

#### Scenario: 誤った値の早期検出

- **WHEN** options に型の合わない値や存在しないオプション名を与える
- **THEN** 構成の評価が失敗する
- **AND** 実機への適用を待たずに CI で検出される
